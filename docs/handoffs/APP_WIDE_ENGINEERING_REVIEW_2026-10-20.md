Protocol export reads are strict: unreadable or malformed existing history is not treated as an empty run. In-process step updates are serialized. Before replacing a history document, the previous bytes are copied to a UUID-named recovery document and read back. Replacement is in place and read back, preserving the original document identity. A failed write attempts restoration; a failed restoration retains and identifies the recovery copy. This is recoverability, not a promise of universal SAF atomicity or crash-time automatic recovery.

Unlike Downloads rollback, failed legacy packages can leave already copied files/empty folders. Failed protocol recovery-copy cleanup can leave a valid extra copy. Provider-specific SAF failure behavior, cloud-sync durability, legacy pre-Android-10 storage and process/power-loss recovery remain open. Synchronous package/Save actions can still block the UI on slow providers. No existing user exports are migrated or deleted by this review.
