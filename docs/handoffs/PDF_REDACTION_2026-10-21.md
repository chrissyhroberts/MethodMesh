## Redaction boundary and trade-offs

Each page is rendered on white, the marked pixels are replaced with opaque black before export, and a fresh Android PDF document receives only those masked bitmaps. Rectangle bounds round outward with a one-pixel guard. The new PDF does not copy original text streams, fonts, metadata, editable forms, annotations, links, embedded attachments, incremental revisions or digital-signature structures. It has a generic generated filename and an output SHA-256. Successful interactive result evidence does not add the source URI/path/name.

The output is an image-based 150 dpi document, not a searchable/editable/vector-preserving or accessibility/tagging/signature-preserving PDF. Unmasked information is still visible and can be OCRed. Users must cover the entire sensitive region and review every exported page. This is not secure erasure of the original on the phone; that file is intentionally untouched.

Safety limits: 64 MiB source, at most 50 pages, 12 million rendered pixels per page and 40 million total. This bounds the native PDF document's image memory; ordinary A4 documents hit the pixel bound before 50 pages. Oversized/password-protected/unreadable documents fail visibly and may need to be split/unlocked first. Blocking native/provider calls may finish before cancellation is observed. Crash-time cache cleanup, durable drafts, whole-process recovery, hostile-document fuzzing, low-memory/old-phone stress and actual receiver/SAF behavior are not certified.

The canonical interactive method/settings/output contract is documented in the module README. Headless execution fails explicitly. Existing image XLSForms are unchanged; a dedicated PDF XLSForm and real Collect/Enketo/preset/protocol roundtrips remain follow-up acceptance work.
